For the coloring implementation, a Queue based Breadth First Search Flood Fill algorithm was chosen to eliminate the risk of StackOverflow exceptions on large pixel arrays. To ensure the application remains responsive and does not freeze the screen during large fills, this BFS logic is executed asynchronously on a background worker thread. Level progress is managed through 2 approachs: completion threshold flags are saved using Unity's native 'PlayerPrefs', the actual modified pixel data is encoded into a PNG format and stored persistently in 'Application.persistentDataPath'. When a level is reopened, this PNG is loaded from the device, converted back into a byte array and applied directly to the canvas texture to resume coloring. If the canvas were scaled up to 2048x2048 resolution, the current architecture would face performance bottlenecks. Processing over 4 million pixels per fill would cause extreme memory spikes due to the pixel array copies and queue allocations, this could lead to Out-Of-Memory crashes on some mobile devices. Also, encoding a 2048x2048 texture into a PNG synchronously during the save step would block the main thread long enough to cause a noticeable freeze for the player.
